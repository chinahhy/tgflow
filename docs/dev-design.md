# dev 界面设计与验收记录

## 设计约定

以桌面概览概念图为视觉基准：浅灰蓝左侧导航、白色主区域、蓝色强调、四项开放式统计、下载表格和最近完成的三列封面。沿用项目的 Next.js、React、shadcn/ui 与 Lucide，不引入新的 UI 框架。

桌面导航宽 292 px，折叠后 76 px；主区域左右留白 44 px。标题在桌面为 44 px，统计数值 48 px，导航 18 px；表格和封面保持统一圆角与细边框。窄屏使用抽屉导航、两列统计、任务纵向信息和单列封面。真实附件封面由 Telegram 缩略图提供，无缩略图时显示明确的文件类型。

## 视觉核对

概念图原尺寸为 1505 × 1045。浏览器以该视口和 390 × 844 手机视口验证；完整页面截图可能高于视口。使用 `view_image` 直接读取概念图及最新浏览器截图，逐项比对，另用 IAB 操作导航、语言与指南，并检查控制台。

| 核对点 | 概念图与渲染证据 | 调整／结论 |
| --- | --- | --- |
| 布局 | 固定左栏、四项统计、表格、三列封面顺序相同 | 将左栏从 280 调到 292 px，保持主区域对齐 |
| 字体 | 初次渲染标题、导航、计数偏小 | 调整桌面标题 44 px、导航 18 px、计数 48 px，统一表格字号 |
| 间距 | 初次标题偏低，大小列偏右 | 缩短桌面顶部栏，调整主区域留白和表格列比例 |
| 配色与容器 | 白色主背景、浅色侧栏、蓝色选中项、细边框表格 | 使用语义颜色，深色模式单独适配；统计不额外套卡片 |
| 文案与图标 | 七项导航、四种下载状态、查看全部、暂停／继续／重试 | 保持入口顺序；图标沿用统一线性风格与可访问名称 |
| 封面 | 概念为照片；测试截图为可重复的合成缩略图 | 有意差异，仅测试夹具使用 SVG；产品读取实际 Telegram 媒体 |
| 响应式 | 概念以桌面为主；手机需要完整操作 | 抽屉导航、换行页签、单列任务，检查横向无溢出 |

首屏文案差异为有意调整：“下载中”统一为“正在下载”；补充失败发生时间、退出登录，以及永久移除的平台分享／BT 入口。测试图中的账号、文件、计数、进度和封面均为合成数据，未作为产品默认内容。开发模式的 Next.js 调试标记不进入正式导出。

已修复初版主要排版偏差，按上述有意差异完成设计核对。动态列表会随实际数据量改变高度；不以固定三条记录或示例进度替代真实状态。

## 交互与验证边界

Playwright 用独立浏览器配置和可控 API 响应检查登录隔离、CSRF、折叠偏好、七入口、失败记录、暂停请求、自动化设置实际保存值、筛选 URL、稀疏结果继续分页与手机导航。它补充 IAB 手动检查，用于可重复回归；本机使用系统 Chrome 测试程序是因为 Playwright 缓存中没有 Chromium，未操作用户的 Chrome 配置或会话。

后端另以真实 SQLite 和可控 TDLib 网关验证磁盘路径、原名、失败持久化、下载状态转换、预览与删除。浏览器演示不代表真实 Telegram 网络或 NAS 已验收，部署说明见 [dev-guide.md](dev-guide.md)。
